# 議事録作成ツール

Discord の通話を録音し、自動で文字起こし・議事録作成まで行うツールです。

Discord でボタンを押して会議をし、もう一度ボタンを押すと、

1. 話者ごとの音声を保存
2. 文字起こし（誰がいつ何を言ったか付き）
3. Gemini で議事録に要約
4. できあがった議事録を Discord に投稿

までを自動で行います。

手元に音声ファイルがある場合は、Discord を使わず処理することもできます（下記「手動モード」）。

---

## ⚠️ 最重要：会議は「ステージチャンネル」で行うこと

**通常のボイスチャンネルでは録音できません。** 必ずステージチャンネルを使ってください。

理由は Discord 側の仕様変更です。Discord は 2026年3月2日に音声通話の
E2E暗号化（DAVE プロトコル）を必須化しました。DAVE に対応していない
クライアントは通常のボイスチャンネルへの接続を拒否されます
（`WebSocket closed with 4017`）。bot が使うライブラリ py-cord は
まだ DAVE に対応できていません（[issue #3139](https://github.com/Pycord-Development/pycord/issues/3139) で対応中）。

**ステージチャンネルはこの必須化の対象外**なので、そちらでなら録音できます。

### ステージチャンネルの準備（初回のみ）

1. サーバー設定 →「有効化」→ **コミュニティサーバーを有効にする**
2. チャンネル作成時に種類で **ステージチャンネル** を選ぶ
3. 「非公開チャンネル」はオフのままにする
   （オンにする場合は、bot のロールに「チャンネルを見る」「接続」を許可する）

### 会議のたびに必要なこと（参加者の操作は1クリックだけ）

ステージチャンネルは、参加者が最初「聴衆」になり、そのままでは音声が流れません。
bot が以下を自動でやるので、**参加者は出てきた「追加」を1回押すだけ**です。

- ステージが立っていなければ**自動で開始**する
- 入ってきた人に**スピーカー招待を自動送信**する
- 相手が自分で「スピーカーになりたい」を押した場合も**即座に自動承認**する

**最後の1クリックだけは省略できません。** Discord は他人のマイクを
勝手にオンにすることを禁止しており、bot の権限では回避できないためです。
押し忘れると、録音は成功するのにその人の音声だけ入りません。

## 使い方（Discord 自動モード）

1. **ステージチャンネル**に参加する（bot が招待を出すので **「追加」を1回押す**）
2. テキストチャンネルで **`/panel`** を実行してパネルを設置（初回のみ。以後は残ったパネルを使える）
3. **🔴 録音開始** を押す
4. 会議が終わったら **⏹️ 停止して議事録作成** を押す
5. しばらくすると、同じチャンネルに **議事録ファイル**が投稿されます

投稿されるメッセージは3種類です。

| 表示 | 意味 | その後 |
|---|---|---|
| ✅ 議事録が完成しました！ | 成功。議事録を添付 | 音声は自動削除（書き起こしと議事録は残る） |
| ⚠️ 要約に失敗しました | 文字起こしは成功。書き起こしを添付 | bot を再起動すると**要約だけ**自動でやり直す（約30秒） |
| ⚠️ 発言が見つかりませんでした | 録音に音声が入っていない | 会議フォルダに `_no_speech.txt` が残り、以後は再処理しない |

- パネルは bot を再起動しても押せます（永続 View）。
- ボタンの代わりに `/record` `/stop` でも同じことができます。
- 録音・議事録データは `recordings/<日時>/` に保存されます（Git 管理外）。

### 処理にかかる時間（実測）

CPU で文字起こしするため、**録音時間のおよそ2〜3倍**かかります。

| 録音 | 文字起こし | 要約 |
|---|---|---|
| 5分（2人） | 約12分 | 約30秒 |

1時間の会議なら2〜3時間かかる計算です。処理中は PC をスリープさせないでください。

### 議事録作成中に bot を再起動しないこと

処理が中断されます。ただし**再起動しても自動で復旧**します。
bot は起動時に「議事録が出来ていない会議」を探し、続きから処理します。

- 書き起こしが残っていれば**要約だけやり直す**（約30秒。文字起こしはやり直さない）
- 音声しかなければ文字起こしから実行する

進行状況は **`/status`** で確認できます。

### コマンド一覧

| コマンド | 役割 |
|---|---|
| `/panel` | 録音開始・停止ボタンを設置 |
| `/record` | 録音開始（ボタンと同じ） |
| `/stop` | 停止＆議事録作成（ボタンと同じ） |
| `/status` | 録音中か、議事録を作成中かを確認 |
| `/leave` | 強制退出（状態がおかしくなったときの復旧用） |

### bot の起動について

`watch_discord.py` が常駐しており、**Discord を起動すると bot も自動で起動**します
（Discord を終了すると bot も止まります）。Windows のスタートアップに
`MinutesBotWatcher.lnk` として登録済みなので、普段は何も操作不要です。

手動で起動したい場合は `議事録bot起動.bat` をダブルクリックしてください。

## 使い方（手動モード）

Discord を使わず、手元の音声ファイルから議事録を作る場合：

1. フォルダを作り、音声ファイルを入れる（wav / mp3 / m4a / mp4 / flac）
2. そのフォルダを **`議事録作成.bat`** にドラッグ＆ドロップ

**ファイル名がそのまま話者名になります。**`田中.wav` `佐藤.wav` のようにしておくと
議事録が読みやすくなります。ファイル1つの場合もフォルダに入れてください。

処理が終わると、同じフォルダに次の2つができます。

- `<フォルダ名>_書き起こし.txt` … `[00:12:34] 話者名: 発言` を時刻順に並べたもの
- `<フォルダ名>_議事録.txt` … 要約された議事録

| `whisper_utils.py` | 文字起こしの共通処理（モデル読み込み・タイムスタンプ整形） | Python 3.14 |

文字起こし・要約側が torch / transformers / google-genai / python-dotenv です。

> 録音ライブラリ(py-cord)の都合で bot は **Python 3.13**、
> 文字起こし(torch)は **Python 3.14** を使い、bot がサブプロセスで呼び分けます。

## セットアップ（初回のみ）

### 1. Discord bot を用意する

手順は「[付録: Discord に bot アプリを連携する手順](#付録-discord-に-bot-アプリを連携する手順)」に
まとめてあります。**このツールに必要な設定は次の3つ**です。

| 項目 | 値 |
|---|---|
| SCOPES | `bot` と `applications.commands`（**両方必須**） |
| BOT PERMISSIONS | 権限値 `57707536`（下表の9つ） |
| 特権インテント | **不要**（スラッシュコマンドとボイス状態しか使わないため） |

| 権限 | 何に使うか |
|---|---|
| View Channel | チャンネルを見る |
| Send Messages | 議事録の投稿 |
| Attach Files | 議事録ファイルの添付 |
| Connect | ボイスチャンネルへの接続 |
| Speak | ボイス接続の確立 |
| Use Voice Activity | 音声の受信（録音） |
| **Manage Channels** | **ステージの自動開始** |
| **Mute Members** | **参加者へのスピーカー招待・自動昇格** |
| **Move Members** | **ステージモデレーターとして扱われるために必要** |

**太字の3つを忘れないでください。** これが無いと、ステージの自動開始も
スピーカーへの招待も失敗し、毎回すべて手作業になります
（録音自体は動くので気づきにくい）。
サーバー全体に与えたくない場合は、付録の手順4でステージチャンネルにだけ与えられます。

### 2. Gemini API キーを用意する
- https://aistudio.google.com/ で API キーを取得

### 3. `.env` を作る
`.env.example` を `.env` という名前でコピーし、値を設定：

```
DISCORD_TOKEN=（Discordのbotトークン）
GEMINI_API_KEY=（GeminiのAPIキー）
DISCORD_GUILD_ID=（サーバーID。指定するとコマンドが即反映される）
GEMINI_MODEL=（省略可。既定は gemini-flash-latest）
```

> 以下は任意設定です（未設定でも動きます）:
> - `GEMINI_FALLBACK_MODEL` … 本命モデルが混雑(503)や上限(429)で使えないときに切り替える予備モデル（既定: `gemini-flash-lite-latest`）。空にすると切り替えません。
> - `DELETE_AUDIO_AFTER_PROCESSING` … **議事録まで完成したとき**に生の音声ファイルを自動削除するか（既定: `true`）。書き起こし・議事録は残ります。要約に失敗した場合や発言が無かった場合は、やり直せるように音声を残します。
> - `RECORDINGS_RETENTION_DAYS` … `recordings/` 内の古い会議フォルダを bot 起動時に自動削除するまでの日数（既定: `30`。0以下で無効化）。中身が空のフォルダ（接続に失敗した回などで出来る）はこの設定に関係なく削除されます。

### 4. 依存パッケージ（すでに導入済みなら不要）

```powershell
# bot用（Python 3.13の仮想環境）
py -3.13 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-bot.txt

# 文字起こし・要約用（Python 3.14）
py -3.14 -m pip install torch transformers google-genai python-dotenv

# ffmpeg（音声処理）
winget install Gyan.FFmpeg
```

> **py-cord のバージョンは 2.7.2 に固定してください。上げても下げても録音できません。**
> 理由は `requirements-bot.txt` のコメントに詳しく書いてあります。

## トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| `WebSocket closed with 4017` | 通常のボイスチャンネルを使っています。**ステージチャンネル**で行ってください |
| `WebSocket closed with 4006` | py-cord のバージョンが古すぎます（v4 ゲートウェイは廃止済み）。**2.7.2** を入れてください |
| `録音データが空でした` | ステージで**スピーカーになっていない**可能性が高いです。bot が出す招待の「追加」を押してください |
| 特定の人の発言だけ入っていない | その人が招待の「追加」を押していません。押すまで音声は流れません |
| 議事録がいつまでも出てこない | 処理中に bot が止まった可能性があります。bot を起動し直せば自動で再開します（`/status` で確認可） |
| bot がコマンドに反応しない | 招待時に `applications.commands` スコープを付けたか確認 |
| `python.exe - アプリケーションを正しく起動できませんでした (0xc0000142)` が繰り返し出る | Windows のシャットダウン処理中に bot を起動しようとしています。シャットダウンが何かのアプリ（インストーラ等）に阻まれて止まっていると起こります。ウォッチャー側でシャットダウン中は起動しないようにしてあるので、通常は出ません。出た場合は止まっているシャットダウンを完了させてください |
| `ffmpegが見つかりません` | `winget install Gyan.FFmpeg` 実行後、PC を再起動 |
| 議事録が作られず書き起こしだけできる | `.env` の `GEMINI_API_KEY` が未設定です |
| 要約が `429`（利用上限） | 無料枠は**1モデルあたり1日20リクエスト**です。予備モデルへ自動で切り替わりますが、両方使い切った場合は時間をおいてください。書き起こしは残っているので、bot を再起動すれば要約だけ数十秒でやり直します |
| 要約が `503`（混雑） | 本命モデルが混んでいます。**予備モデルへ自動で切り替わる**ので通常は何もしなくて構いません（ログに「予備モデル … で成功しました」と出ます）。両方駄目な場合は時間をおいて bot を再起動してください |
| 文字起こしが遅い | GPU が無く CPU 処理になっています。会議が長いほど時間がかかります |
| 議事録の内容が「特になし」ばかり | 録音に会議の実体が無い場合の正常動作です。`prompt.txt` が「発言されていない結論を作らない」方針のため |

### ログの見かた

| ファイル | 内容 |
|---|---|
| `bot.out.log` | bot の動作ログ。各行の先頭に時刻が付きます |
| `bot.err.log` | bot が異常終了したときのエラー内容。空なら異常終了していません |
| `watcher.log` | 自動起動ウォッチャーの記録（bot の起動・停止・PID） |

**bot が2つ動いているように見えるのは正常です。** venv の `python.exe` は
本体を起動し直す中継スタブなので、1つの bot が OS 上は
［スタブ→本体］の2プロセスに見えます（タスクマネージャーでも2つ出ます）。
本当に多重起動している場合は `watcher.log` に「警告: botがN個動いています」と出ます。

2MB を超えると `*.old.log` に退避して書き直すので、放置しても際限なく大きくなりません。

> 文字起こし・要約（`pipeline.py`）の出力は、サブプロセスが終わってから
> まとめて記録されます。そのため行に付く時刻は**その処理が終わった時刻**です。

### 議事録の書式を変えたいとき

`prompt.txt` を編集してください。既定は**同人サークルのミーティング**向けの
テンプレート（`【議事録】` / `★★★内容★★★` / `★★★宿題★★★`）になっています。
用途が違う場合はここを書き換えます。

## 付録: Discord に bot アプリを連携する手順

このツールに限らず、**Discord の bot アプリをサーバーに入れるときの共通手順**です。
権限の内容だけアプリごとに読み替えてください。

### 手順1. アプリを作る

1. https://discord.com/developers/applications を開く
2. 右上 **New Application** → 名前を付けて作成
3. 左メニュー **General Information** の **Application ID** を控える
   （招待URLに使う。公開しても問題ない値）

> すでにあるアプリを別のサーバーに入れ直すだけなら、この手順は不要です。

### 手順2. トークンを取得する

1. 左メニュー **Bot** を開く
2. **Reset Token** を押して承認（2段階認証を設定していれば認証コードを求められる）
3. 表示された文字列を **Copy**

**トークンは発行時の一度しか表示されません。** 後から見る方法は無いので、
分からなくなったら再度 Reset するしかありません。
また **Reset した瞬間に古いトークンは無効**になり、
それで動いていた bot は即座に切断されます。稼働中のものを触るときは注意してください。

控えたトークンはアプリの設定ファイル（このツールでは `.env` の `DISCORD_TOKEN`）に
貼り付けます。引用符で囲まず、`=` の前後に空白を入れないこと。

> **特権インテント**（MESSAGE CONTENT INTENT / SERVER MEMBERS INTENT）は、
> アプリがメッセージ本文やメンバー一覧を読む場合だけ ON にします。
> スラッシュコマンドとボイスしか使わないアプリでは不要です。

### 手順3. 招待URLを作ってサーバーに入れる

**方法A: 画面で作る**

左メニュー **OAuth2 → URL Generator** で、

- **SCOPES**: `bot` を選択。スラッシュコマンドを使うアプリなら `applications.commands` も
  （**この2つはセット**。`applications.commands` が無いとコマンドが登録されず、
  bot はいるのにコマンドが出てこない状態になる）
- **BOT PERMISSIONS**: 必要な権限にチェック
- 下部に出来た URL をコピー

**方法B: URLを手で組み立てる**

```
https://discord.com/api/oauth2/authorize?client_id=＜Application ID＞&permissions=＜権限値＞&scope=bot%20applications.commands
```

権限値は各権限のビットの合計です。分からなければ方法Aで作れば自動で入ります。
自分で計算したい場合は、py-cord が入っていれば次のように出せます。

```powershell
python -c "import discord; print(discord.Permissions(connect=True, speak=True, send_messages=True).value)"
```

**認証する**

URL を開くと「アプリを追加」画面が出ます。サーバーを選んで **「認証」** を押します。
このとき**サーバーの管理権限を持っているアカウント**でログインしている必要があります。

### 手順4.（必要なら）チャンネル単位で権限を足す

手順3で必要な権限をすべて付けたなら不要です。

サーバー全体に強い権限を与えたくない場合は、**招待は最小限の権限で行い、
必要なチャンネルにだけ追加で与える**という方法が使えます。
Discord の権限はチャンネル単位の設定がサーバー全体の設定に優先するためです。

1. 対象チャンネルの **⚙️（チャンネルの編集）→ 権限**
2. 「メンバーまたはロールを追加」でその bot（またはその bot のロール）を追加
3. 必要な権限だけを ✓（許可）にする

> このツールの「きゃーにー」での実例では、招待時は基本6権限のみで、
> ステージ操作に必要な **チャンネルの管理 / メンバーをミュート / メンバーを移動** の3つを
> ステージチャンネルにだけ与えています。

### 手順5. アプリ側にサーバーIDを教える

スラッシュコマンドを**そのサーバーに即座に**登録するために、多くのアプリは
サーバーID（ギルドID）を設定できるようになっています。
未設定だとグローバル登録になり、コマンドが使えるまで最大1時間ほどかかります。

サーバーIDの調べ方:

1. Discord の設定 → **詳細設定** → **開発者モード** を ON
2. サーバー名を右クリック → **サーバーIDをコピー**

このツールでは `.env` の `DISCORD_GUILD_ID` に設定します。

### 手順6. アプリを再起動して確認する

設定ファイルを書き換えたら**アプリの再起動が必要**です
（このツールでは Discord を終了して起動し直せばウォッチャーが入れ替えます）。

うまくいったかどうかは次で確認できます。

| 確認したいこと | 見かた |
|---|---|
| サーバーに入ったか | メンバー一覧に bot が表示される |
| オンラインか | メンバー一覧で緑の●。灰色ならアプリ側が起動していない |
| コマンドが登録されたか | チャンネルで `/` を打つとコマンド候補が出る |
| 権限が足りているか | サーバー設定 → **連携サービス** から確認、またはチャンネルの権限画面 |

コマンドが出てこない場合は、ほぼ `applications.commands` スコープの付け忘れです。
その場合は**招待からやり直す**（同じURLに`applications.commands`を足して再認証する）と直ります。
